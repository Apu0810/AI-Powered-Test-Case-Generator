Problem Statement: Manual software requirement analysis and test suite authoring are labor-intensive, slow, and prone to cognitive bias. Testers frequently overlook edge boundary conditions, format permutations, and data collisions.

ℹ️ Project Overview & Viva Voce Guide

                
            

            

                
📌 Problem Statement (Task A)

                
Manual requirements analysis and test case authoring often miss edge boundary cases, negative data formats, and duplicate records due to cognitive fatigue. This tool applies structured Generative AI prompts to generate high-coverage test cases across Positive, Negative, Boundary, and Security partitions in seconds.


                
🎯 Key Viva Questions

                

                    
Q: How does the AI generate test cases without paid API keys?
A: It uses an intelligent, transparent keyword-aware local fallback generator that maps requirement entities to Equivalence Class Partitions and Boundary Value rules.

                    
Q: Why are passwords hashed?
A: To prevent plaintext credential exposure during database leaks. We use Werkzeug's cryptographic PBKDF2/SHA-256 algorithm.

                    
Q: What is the boundary value rule for password length?
A: Min 8 characters: 7 chars is Min-1 (Invalid), 8 chars is Min (Valid).
