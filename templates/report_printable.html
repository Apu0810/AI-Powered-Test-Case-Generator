1. Project Title & Problem Statement

Project Title: AI-Powered Software Requirements and Test Case Generator for Student Registration Portal

Problem Statement: In traditional software engineering, the translation of business requirements into rigorous test suites is a manual, human-intensive process. Quality assurance teams often struggle with cognitive oversight—overlooking edge boundary conditions, negative data permutations, and duplicate data hazards under tight delivery deadlines. This results in software bugs escaping into production environments.

Generative AI Value Proposition: Integrating Generative AI into the testing workflow automates requirements analysis. By providing domain context, boundary rules, and formal JSON schemas through structured prompt engineering, the AI engine can generate dozens of positive, negative, and boundary test cases within seconds, reducing test authoring overhead by up to 75% while boosting test coverage and traceability.

2. Objectives

  1. Design and implement a robust, secure Student Registration Portal with strict server-side validation and password hashing.
  2. Implement a Generative AI prompt framework capable of parsing functional requirements and generating structured test cases with zero hallucinations.
  3. Provide an intelligent, deterministic fallback generator ensuring 100% test case generation without dependency on paid external APIs.
  4. Support both live automated test execution against backend REST APIs and manual tester recording.
  5. Track and document software defects systematically without fabricating false failures.
  6. Generate standardized testing deliverables including CSV exports and printable audit reports.

5. Generative AI Prompt & Prompt Engineering (Task C)

The system utilizes role-based few-shot prompt engineering with strict JSON schema constraints:

SYSTEM PROMPT:
You are a Senior Software Quality Assurance Engineer and Testing Automation Specialist.
Your task is to analyze software functional requirements and generate rigorous, structured test cases.

Testing Principles to Apply:
1. Equivalence Class Partitioning (Valid and Invalid partitions).
2. Boundary Value Analysis (Min, Max, Min-1, Max+1 boundaries).
3. Negative Testing & Input Validation (Empty fields, wrong formats, special characters).
4. Data Integrity & Security (Duplicate entries, length restrictions).

Output format MUST be a strict JSON list of test case objects with keys:
- tc_id: Unique string, format "TC--"
- req_code: String requirement identifier (e.g., FR1, FR2)
- scenario: Clear description of what is being tested
- test_type: One of ["Positive", "Negative", "Boundary", "Security"]
- input_data: JSON object containing user input parameters
- expected_result: Expected HTTP status code and system response
- actual_result: Empty string ""
- status: "Not Executed"
- defect_desc: Empty string ""
